# Issue #363: 404 pages logged as fatal request errors

## Finding

Nitro (`nitropack/dist/runtime/internal/error/prod.mjs`) logs a
`[request error] [fatal|unhandled] [GET] <url>` block with the full error
object only for errors that are `fatal` or `unhandled`. The catch-all page, the
home page and `/kontakt` threw their 404 with `fatal: true`, so every scanner
request (`/.env`, `/.git/config`, `/api/v1/.env`, …) produced such a block.

Container logs in OpenObserve (`docker_logs`, 2026-09-19 to 2026-09-21):

| Container               | `[fatal]` blocks (3 days) |
| ----------------------- | ------------------------- |
| `lafattoria-storefront` | ~2,500                    |
| `shopbite-storefront`   | 565                       |
| `shopbite-homepage`     | 423 (same pattern, own repo) |

`fatal` cannot simply be dropped: Nuxt's root component
(`nuxt/dist/app/components/nuxt-root.vue`, `onErrorCaptured`) shows the error
page on the server for every error, but in the browser only for fatal ones. A
non-fatal 404 during client-side navigation would leave the page blank.

## Fix

`createNotFoundError()` (`app/utils/notFound.ts`) throws the 404 with
`fatal: import.meta.client`. The catch-all page passes 5xx errors of the content
route on as a fatal 500 (logged, a real failure); 4xx of that route count as
"not found" (it rejects over-long scanner paths with 400).

## Verification

Production build against the demo backend: `/.env`, `/.git/config`,
`/firebase-key.json`, `/gibtesnicht` and a 300-character path return 404 with
the error page and add no line to the server log; `/` is 200. Client-side
navigation to an unknown path still shows the error page.

## Other findings

- 117 `[unhandled]` errors on `/api/category|listing|product/*` at La Fattoria,
  all on 2026-09-19 18:00 UTC: the Shopware backend answered with
  `404 page not found` (backend unreachable). Logged correctly; the URL shows a
  double slash (`/store-api//category/…`) because the endpoint env ends in `/`.
